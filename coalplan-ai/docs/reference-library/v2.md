# 优秀施组原子库 V2

## 目标

V2 将优秀施组正文转化为可追溯、可参数化、可审核的技术原子。历史施组只提供工艺组织、控制逻辑和专业表达；当前项目事实仍只能来自投标证据、项目记忆或用户确认。

## 数据流

```text
只读 Markdown
  -> 标题树与结构片段
  -> AI 章节路由（技术原子/章节样本/项目事实/排除）
  -> AI 语义切分与受控标签
  -> 程序兜底识别数值、标准和项目实体
  -> 参数化模板与发布门禁
  -> 人工批量发布
  -> SQLite FTS + Qdrant/BGE 向量
  -> RRF 融合、标签重排与生成引用
```

章节路由与专业标签由模型判断。代码中的正则只负责发现可能泄漏的数值、单位、规范编号和项目实体，不负责决定工程专业或工艺类别。

## 原子契约

每条 V2 原子同时保存：

- `raw_excerpt`：逐字可回查的来源引文。
- `normalized_text`：清理重复行和页码后的正文。
- `parameterized_template`：参数槽替换后的生成参考文本。
- `chapter_module`、`engineering_system`、`engineering_object`、`process_family`、`process_stage`。
- `action_sequence`、`control_points`、`acceptance_checks`、`exceptions`、`risks`。
- `parameter_slots`：原值、单位、语义角色、复用策略和来源位置。
- `publication_blockers`：发布前必须解决的问题。

受控标签位于 `config/reference_library/reference_atom_taxonomy.v2.json`。模型提出的新专业词后续应进入别名或待确认标签，不直接改动代码词表。

## 发布门禁

V2 原子只有同时满足以下条件才能发布：

1. 具有文档模块，以及工程系统或工程对象。
2. 工艺、控制、检查和异常类原子具有明确工艺族。
3. 来源中的带单位数值、规范编号和项目实体全部进入参数槽。
4. 原文长度或结构化控制信息足以表达完整技术含义。
5. 状态处于人工可审阅的 `pending_publish`，再由单条或批量接口发布。

短而明确的禁止条款不采用统一 80 字门槛；系统根据原子类型及控制点完整性判断。

## 检索架构

当前实现采用：

- SQLite FTS5：专业名称、工序词、规范编号等精确召回。
- `BAAI/bge-small-zh-v1.5`：本地生成中文语义向量，在当前 482 条已发布 V2 原子上已完成实际索引。
- Qdrant：存储向量和标签 payload，支持模块、工程系统与明确工艺族过滤。
- RRF：融合词法和向量排名，再按工程对象、工序阶段、内容功能和质量分加权。
- LLM rerank：只处理融合后的少量候选，不扫描全库。

工程对象、工序阶段和内容功能是软匹配项，不能全部做精确过滤，否则会漏掉同一章节内的相邻工序原子。

## API

```text
POST /reference-library/import-ai-v2
POST /reference-library/atoms/bulk-publish
POST /reference-library/retrieve-v2
```

旧接口继续保留。V1 原子不会自动进入 V2 检索。

## 全量语料结果

```powershell
$env:PYTHONPATH='src'
python -m coalplan.interfaces.cli.reference_v2_corpus prepare `
  --source-root 'D:\Task_md\安能-数据-markdown\方案大模型资料\方案大模型资料_清洗归类_最终_20260908\施组文档' `
  --output-dir '.coalplan-data\reference-library\v2-corpus'
```

全量任务已完成，结果如下：

- 输入 42 份施组 Markdown，共 10,748,635 字符、29,892 个结构片段。
- AI 章节路由 42/42 完成，189 次路由调用选出 13,417 个有效片段。
- 41 份文档生成 5,593 条 V2 原子；1 份签批、封面类文档被自动排除。
- 原子平均质量分 0.9369，共识别 15,477 个参数槽。
- 分类覆盖 17 种章节模块、16 个已标注工程系统和 28 个工艺族。
- 归并检测得到 193 个近重复组；收紧比较边界后保留 9 个真实参数冲突供审核。

语料运行和物化按文档、批次独立落盘，中断后可续跑；数据库同步不会自动发布候选原子。

## 发布与索引状态

当前已将 41 份有效文档和 5,593 条 V2 原子同步至项目 SQLite 数据库。为避免未经筛选的大批候选内容直接干扰生成，首轮只发布：

- 446 条高质量、高置信、去重且无冲突的代表原子，覆盖全部 41 份有效文档。
- 36 条由真实查询场景反向选出的补充原子，补齐钻爆、混凝土温控和固结灌浆的 Top-k 覆盖。

首轮合计发布 482 条。真实生成后的抽样复核将 1 条适用边界不清的钻爆原子退回待发布并从 Qdrant 删除，因此当前为 481 条已发布、5,069 条 `pending_publish`、43 条 `ai_candidate`。只有 `published + V2 + 无 publication_blockers` 的原子能进入章节生成。

## 真实检索与生成验证

检索集使用自身模型对三类真实章节请求进行结构化查询分类，再执行标签硬边界、FTS 词法召回、BGE 向量召回和 RRF/质量重排。三个场景均稳定返回 5 条：

- “隧洞钻爆开挖施工”：前 5 条以地下洞室钻孔爆破、洞口及不同围岩级别工法为主。
- “大坝混凝土温控与养护”：前 5 条覆盖大体积混凝土温控、通水冷却、夏季施工和养护闭环。
- “引水隧洞固结灌浆施工”：前 3 条为隧洞围岩固结灌浆和压力控制，后 2 条中存在同工艺族相邻工序。

随后对数据库中的真实项目“雅砻江两河口水电站库区复建县道”执行章节生成，节点为“8.3 测量放样、钻孔与装药爆破”：

- 实际新增引用 7 条 V2 原子；查询到的 5 条旧原子使用记录来自 2026-08-30，不属于本次运行。
- 生成后抽查发现其中 1 条同时包含两种起爆网路表述且适用边界不清，已退回待发布；删除后三类回归检索仍为 5/5/5。
- 生成分为 4 个写作单元，完成来源映射、原子检索、逐单元写作、事实泄漏审计和版本保存。
- 正文中出现的 YT-28、φ42 等设备和参数均能在当前投标证据中找到支持，未检出异项目原子参数直接迁移。
- 运行使用 `gpt-5.6-luna`，10 条调用轨迹，总计 316,615 输入 tokens（其中 95,488 缓存输入）、6,811 输出 tokens 和 2,042 推理 tokens。

生成完成后，用户可编辑 Markdown 仅保留章节标题与正文；来源映射、原子 ID、审查结果和待补事项保留在独立生成凭据中。

主要验证产物位于 `.coalplan-data/reference-library/v2-corpus/`：

- `atom_catalog.v2.json`：全量原子分类统计。
- `curation_report.v2.json`：重复组与参数冲突。
- `retrieval_validation_final.v2.json`：三个真实检索场景的分类、候选和排名。
- `chapter_generation_validation.v2.json`：真实项目章节、使用原子、阶段进度、轨迹和 token 消耗。

## 当前边界

当前版本适合进入真实项目的小范围试用，不宜宣称为无需人工复核的最终库：

- 5,068 条通过基础门禁的候选原子尚未全部人工发布，这是有意保留的审核边界，不是处理中断。
- 同一工艺族内的相邻工序仍可能出现在第 4～5 名，生成前仍应在小页窗中允许用户锁定、排除或替换。
- 参数冲突检测能组织可审核的候选，但不能替代工程师对适用条件、设计版本和现场试验的判断。
- 仍需逐步积累带人工标注的多项目查询集，长期监测 Top-k 相关率、无结果率和事实泄漏率。
