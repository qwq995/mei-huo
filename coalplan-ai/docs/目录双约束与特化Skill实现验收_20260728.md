# 目录双约束与特化 Skill 实现验收

## 一、实现范围

本轮完成以下链路：

1. 初始目录同时受施组模板和投标文档目录约束。
2. 模板顶层章节及既有节点保持稳定，投标目录与特化 skill 只在模板锚点下增加细粒度子节。
3. 目录生成后，依据项目画像和投标目录证据生成项目概况与逐节点章节概况。
4. 安全、工艺、质量、环境、进度资源五类章节使用独立 skill 扩充目录并辅助正文生成。
5. 特化 skill 命中后成为该节点唯一主写作模式，避免旧模式库把质量、环保、进度等整章要求同时施加到单一安全或工艺子节。
6. 目录节点的来源、模板锚点、skill、章节概况和生成追溯信息进入数据库与 API。

## 五、已处理的实现风险

- 防止 AI 删除、改名或重排模板硬骨架。
- 防止动态节点脱离模板锚点或引用不存在的投标 `section_id`。
- 防止仅凭上下文普通词误用 skill。
- 处理`安全监测`与职业安全、`施工期水流控制`与工期管理的中文歧义。
- 防止格式修复和篇幅压缩丢失 `evidence_id` 与写作模式要求。
- 防止多级编号如`6.4.3.1项目部`被误抽取为`3.1项`。
- 防止“人员持证要求”被误判为已经提供人员名单和证书编号。
- 防止旧模式库把多个完整管理章要求叠加到单一特化子节。
- 单章生成 API 直接返回 `generation_metadata` 与 `evidence_audit`，便于前端展示和问题定位。
